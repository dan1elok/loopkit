# Loop Watch — 2026-09

First digest. A few sources, not a dump.

- [The Ralph Wiggum technique](https://ghuntley.com/ralph/) — still the
  clearest origin write-up for restart-until-done coding loops.
  **Missing:** a shared library of *jobs*, not just another runner.
- [What is the Ralph technique?](https://ralphloop.sh/blog/what-is-the-ralph-technique/)
  — filesystem-as-memory explained without framework lock-in.
- [The 98% problem (harness engineering survey)](https://labs.beconfident.app/papers/harness-engineering-survey)
  — names silent failure, retry storms, and tool overload as harness
  bugs, not model bugs. This is why LoopKit treats gates as load-bearing.
